# Session Continuity

## Purpose

Runtime セッションごとの実行環境を分離しつつ、会話履歴と作業ファイルを呼び出し間および Runtime 停止・再開後にも継続できることを確認する。

## Requirements

### Requirement: 同一セッションでの会話継続
CLI は同じ Runtime セッション ID を指定した再呼び出しを許可し、エージェントは前回の会話内容を踏まえて応答しなければならない (SHALL)。会話ターンは AgentCore Memory に保存・取得できなければならない (SHALL)。

#### Scenario: CLI を 2 回起動する
- **WHEN** 1 回目の CLI 呼び出しで検証用の事実を伝え、2 回目の別プロセスから同じセッション ID でその事実を質問する
- **THEN** エージェントは前回の事実を答え、対応するユーザー・アシスタントのターンが Memory から取得できる

#### Scenario: Memory イベントだけを使ったアイドル終了後の会話再開
- **WHEN** session storage を無効にした Runtime で検証用の固有事実を会話し、アイドルタイムアウト後に同じ Runtime session ID で新しい実行環境を起動する
- **AND** エージェントが `actorId` と Runtime `sessionId` を指定して AgentCore Memory のイベントを取得し、新しい SDK 会話のコンテキストとして渡す
- **THEN** `instance_id` が切り替わった状態でエージェントは固有事実を答え、SDK の以前の session ID や workspace の永続データを使わずに会話を継続できる

このシナリオは短期会話イベントの保存・取得を検証し、長期 Memory strategy による抽出・意味検索とは区別する。

#### Scenario: 異なるセッション ID
- **WHEN** 別のセッション ID で同じ質問をする
- **THEN** 前のセッションの会話内容は引き継がれない

### Requirement: ワークスペースの永続性
エージェントはセッション固有のワークスペースにファイルを書き、同じセッション ID の後続呼び出しと Runtime 停止・再開後に読み取れなければならない (SHALL)。

#### Scenario: 2 回の CLI 呼び出しでファイルを再利用する
- **WHEN** 最初の呼び出しで検証用ファイルを保存し、次の呼び出しで同じセッション ID を指定する
- **THEN** 2 回目にファイル内容を読み取れる

#### Scenario: 停止後の再開
- **WHEN** ファイルを保存し、Runtime セッションの停止完了を待ってから同じ ID で再呼び出しする
- **THEN** 新しい実行環境でもファイルと会話を参照できる

### Requirement: セッション分離と実行環境の終了
異なる Runtime セッション ID の実行環境は分離され、停止したセッションの実行環境は終了しなければならない (SHALL)。再呼び出しで同じ ID のセッションを再開する場合は新しい実行環境が割り当てられなければならない (SHALL)。

#### Scenario: 同時に異なるセッションを起動する
- **WHEN** 2 つの異なるセッション ID で呼び出す
- **THEN** 一方のワークスペースと会話は他方から参照できず、実行環境の識別情報も異なる

#### Scenario: 実行環境を停止して再開する
- **WHEN** セッションを停止し、停止完了後に同じ ID で呼び出す
- **THEN** 停止前後の実行環境識別情報は異なり、セッションストレージのデータは引き継がれる
